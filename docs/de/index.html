Rechts- und Sicherheitslücken finden, die beim Coden mit KI durchrutschen

rechtzeitig ist eine GitHub Action, die Ihr Repository und Ihre Live-Website prüft: Impressum, Datenschutzerklärung, Cookie-Einwilligung, geleakte API-Keys, Security-Header, verwundbare Pakete. Jeder Befund nennt die Stelle und das Gesetz.

Workflow kopieren Alle 56 Prüfungen ansehen

Kostenlos und Open Source von kreativ-anders. Kein Konto; der Code bleibt auf Ihrem Runner.

geprüftrechtzeitig

In einem Schritt einbauen

rechtzeitig.yml nach .github/workflows/ im eigenen Repository kopieren und die url eintragen. Der Workflow läuft jeden Montag, und GitHub schreibt Ihnen, wenn eine Prüfung fehlschlägt. Alle Optionen: Konfiguration (Englisch).

Was geprüft wird

  • Repository

    Eingecheckte Schlüssel, bekannte Schwachstellen, Lizenzen, riskante Workflows, offene Datenbankregeln. Dazu eine CycloneDX-SBOM.

  • Website

    Impressum, Datenschutzerklärung, Cookies vor der Einwilligung, Security-Header und TLS, Kündigungsbutton. Läuft, wenn Sie eine url angeben.

  • Beides zusammen

    Ein Lauf, ein Bericht. Prüfungen, die beide Seiten vergleichen, stehen auf der Roadmap.

Quellen statt Rechtsberatung

Jede Prüfung nennt ihre Rechtsgrundlage und verlinkt Primärquellen: Gesetze, Gerichte, Behörden.

Alle 56 Prüfungen wurden zuletzt zwischen dem 3. November 2026 und dem 4. November 2026 mit ihren Quellen abgeglichen. Eine Prüfung, die ein Jahr lang nicht abgeglichen wurde, lässt die Tests des Projekts scheitern.

Fragen

Wie bekomme ich die neueste Version?

Der Workflow pinnt ein Release über seinen Commit-SHA. Mit .github/dependabot.yml im Repository öffnet Dependabot für jedes neue Release einen Pull Request:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
Verlassen Daten den Runner?

Der Quellcode nicht. Standardmäßig gehen Paketnamen und Versionen an osv.dev und der Hostname an die Green Web Foundation; beides lässt sich abschalten. Siehe Daten, die den Runner verlassen.

Wer kann den Bericht sehen?

In einem öffentlichen Repository zeigt die Seite des Laufs nur die Zahlen. Die Befunde gehen in den Security-Tab, den nur Personen mit Schreibrechten sehen. Siehe Der Bericht.

Befunde sind technische Risikohinweise mit Fundstelle und Rechtsgrundlage, keine Rechtsberatung.
