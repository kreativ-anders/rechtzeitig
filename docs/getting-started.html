Get started

From an empty repository to a first report in about ten minutes: copy one file, set your start page, decide on three opt-ins, start the run. Nothing about your project leaves the runner unless you turn it on.

§ 1Copy the workflow

Create .github/workflows/rechtzeitig.yml in your repository (on GitHub: Add file → Create new file) and paste this file. It pins a release by its commit SHA, checks out the repository without keeping the token (persist-credentials: false) and needs no secret.

# Copy to .github/workflows/rechtzeitig.yml in your repository and set url. It then runs every Monday.
# To run it now: Actions → rechtzeitig → Run workflow.
# Docs: https://rechtzeitig.dev/workflow.html
name: rechtzeitig

on:
  schedule:
    - cron: "17 5 * * 1" # Mondays, 05:17 UTC. A minute other than :00 avoids GitHub's busiest time.
  workflow_dispatch:

permissions:
  contents: read

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      # Findings as alerts in the Security tab (sarif-upload: auto). Where GitHub does not allow it,
      # for example in private repositories without GitHub Code Security, the upload is skipped with a notice.
      security-events: write
      actions: read # needed by the upload in private repositories
    timeout-minutes: 20
    steps:
      # Lets rechtzeitig read lockfiles, licenses and secrets. Remove to scan the website only.
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      # Pinned to a release. Dependabot can move the pin: https://rechtzeitig.dev/#updates
      - uses: kreativ-anders/rechtzeitig@4578635acd60d75a3f4a06e637d1ed789d4a3c31 # v0.6.0
        with:
          # Start page of your site. Without url only the repository is checked.
          # url: https://www.example.de/
          # Language of the site: de, en, a list such as de,en, or all.
          language: de
          # true if consumers buy or sign contracts on the site (shop checks).
          sales: false
          # true if visitors can sign up for subscriptions (cancellation button, § 312k BGB).
          subscriptions: false
          # The job fails when a check fails, so GitHub emails you about new findings of a scheduled run.
          # never = report only, warn = also on warnings.
          fail-on: fail
          # Opt-in: with the secret IPINFO_TOKEN (free at ipinfo.io) the third-country check also looks up IP countries.
          # Without the secret it uses the countries in its data and nothing is sent to IPinfo.
          ipinfo-token: ${{ secrets.IPINFO_TOKEN }}
          # Opt-in: true sends the name and version of every locked component, internal packages included,
          # to api.osv.dev to find known vulnerabilities. false = nothing is sent and the check is skipped.
          vulnerabilities: "false"
          # Opt-in: true sends the site's host name to api.thegreenwebfoundation.org for the green hosting check.
          # false = nothing is sent and the check is skipped.
          green-hosting: "false"
          # Optional, shown with their defaults:
          # How much of the report the run shows. auto = full if private, counts if public.
          # full = everything, also on a public repository, where anyone can read it.
          # report-visibility: auto
          # Security tab upload: auto = where GitHub allows it, false = never.
          # sarif-upload: auto
          # Only these check groups (legal, privacy, security, sustainability, accessibility, quality)
          # or scopes (website, repository; repo = repository). Empty = all.
          # modules: ""
          # Language of the report (de or en). Empty = language of the site.
          # report-language: ""
          # Pages to visit at most.
          # max-pages: "10"
          # false scans without Chrome's sandbox where the runner has none. Only for sites you trust.
          # require-sandbox: "true"

The same file on GitHub: examples/workflows/rechtzeitig.yml.

Never run it on pull_request_target. See Safe use.

§ 2Set these

These lines in the with: block decide what is checked. Change them to fit your site.

InputIn the exampleChange it when
urlcommented outYour site is online: remove the # and set your start page, for example https://www.example.de/. Without it only the repository is checked.
languagedeThe site is in English (en) or in both (de,en).
salesfalseConsumers buy or sign contracts on the site. Turns on the shop checks.
subscriptionsfalseVisitors can sign up for subscriptions. Turns on the cancellation button check.
fail-onfailFor the first runs, never keeps the run green while you fix the findings. warn also fails on warnings. See fail-on.

§ 3Decide what may leave the runner

Your source code never leaves the runner. The scan talks to your website and to GitHub. Lookups at other services are off until you turn them on, so the default run sends nothing about your project to a third party. Each one runs a check that is skipped without it.

Turn on withSendsToRuns
vulnerabilities: "true"Name and version of every locked component, internal packages includedapi.osv.devKnown vulnerabilities and the vulnerabilities in the SBOM
green-hosting: "true"Host name of the start pageapi.thegreenwebfoundation.orgGreen hosting
ipinfo-token with the secret IPINFO_TOKENIP addresses of your server and of the servers it contactsipinfo.ioIP countries in the third-country check

The vulnerability lookup is the one most projects want. The example already passes ipinfo-token; it does nothing until you add the secret under Settings → Secrets and variables → Actions. If your security team reviews outside connections, show them this table and Data that leaves the runner, which also lists what the setup downloads.

§ 4Optional: leave as is

The example names these as comments with their defaults. Most projects never change them.

InputDefaultChange it when
report-visibilityautoYou want the full report on the run page of a public repository, where anyone can read it (full). See The report.
sarif-uploadautoYou do not want findings in the Security tab (false).
modulesallYou want only some groups or scopes, for example legal,privacy or repository.
report-languagelanguage of the siteThe report should be in another language than the site (de or en).
max-pages10Your site has more pages worth a visit, or the run takes too long.
require-sandboxtrueThe runner cannot start Chrome with its sandbox. Only for sites you trust; see Safe use.

§ 5Staging, preview and internal sites

Private or local hosts are allowed for the url host only; third parties and redirects on private addresses stay blocked. Three setups:

  • Preview URL (Vercel, Netlify): take it from a previous step's output. 
    - uses: kreativ-anders/rechtzeitig@…
  with:
    url: ${{ steps.deploy.outputs.preview-url }}
  • App started in the same job: the input host may be localhost. 
    - run: |
    npm start &
    sleep 5
- uses: kreativ-anders/rechtzeitig@…
  with:
    url: http://localhost:3000/
  • Intranet: use a self-hosted runner that can reach it. Only the url host is contacted, nothing else on the private network. 
    jobs:
  scan:
    runs-on: self-hosted

§ 6Permissions

The example asks for as little as it needs. Keep these lines:

  • contents: read lets the checkout read the repository.
  • security-events: write puts the findings in the Security tab.
  • actions: read is needed for that upload in private repositories.

In a private repository without GitHub Code Security the upload is skipped with a notice; the findings are then on the run page and in the artifact rechtzeitig-report. See Security tab.

§ 7Start the first run

Commit the file, then open Actions → rechtzeitig → Run workflow. A run with a website takes a few minutes.

  • Private repository: the full report is on the run page, and in the artifact rechtzeitig-report.
  • Public repository: the run page shows only counts; the findings go to the Security tab, which only people with write access see.

The first run is often red. Set fail-on: never until the findings are fixed. More: The report.

§ 8Keep it running

The example runs every Monday, so a new tracker, an expiring certificate or a newly published vulnerability shows up a week later at most. Set fail-on: fail once the first findings are fixed.

To get each new release as a pull request, add .github/dependabot.yml:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly

See Updates.

Checklist

  • .github/workflows/rechtzeitig.yml committed
  • url, language, sales and subscriptions fit your site
  • Opt-ins decided: vulnerabilities, green-hosting, IPINFO_TOKEN
  • First run started under Actions
  • Findings found on the run page or in the Security tab

Findings are technical risk hints with location and legal basis, not legal advice.
