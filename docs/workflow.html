§ 1Add the workflow

Copy the example workflow to .github/workflows/rechtzeitig.yml. It runs every Monday at 05:17 UTC and from Actions → rechtzeitig → Run workflow. Uncomment url and set the other values in its with: block:

url: https://www.example.de/
language: de
sales: false
subscriptions: false
fail-on: fail # red when a check fails

A failing check turns the run red, and GitHub notifies the person who last changed the cron line. The first run often is red; set fail-on: never for quiet runs until the findings are fixed. In a public repository, GitHub turns the schedule off after 60 days without activity.

To also run on each push, add push: branches: [main]. Never use pull_request_target, see Safe use.

§ 2Inputs

Every input is optional. An input left out or empty uses its default.

Repository checkout

The repository checks read what actions/checkout leaves: by default the current commit, without submodules and LFS files. To scan those too:

- uses: actions/checkout@<sha>
  with:
    persist-credentials: false
    submodules: recursive # files of submodules
    lfs: true             # LFS files instead of pointers
    # token: ${{ secrets.SUBMODULES_TOKEN }} # only for private submodules

Private submodules need a token with contents: read on them, stored as a secret.

The git history is not read: a secret removed in an earlier commit is not found. Files over 1 MB (lockfiles over 50 MB) and binary files are skipped. The summary lists what was not read under Scan.

§ 6The report

report-visibility decides how much the run shows:

ValueShows
autoEverything for private and internal repositories. For public ones only the counts per status; the details go to the Security tab.
fullEverything, also on a public repository, where anyone can read it.

The run summary shows the findings and the checks that did not run. Findings in a repository file also show as annotations. The artifact rechtzeitig-report contains:

FileContent
rechtzeitig-report.mdThe same report as Markdown
rechtzeitig-report.jsonEvery result with rule id, severity, status, message and locations; because for skips, coverage for what was not read
rechtzeitig-sbom.cdx.jsonSBOM in CycloneDX 1.6 format, with vulnerabilities

Secret values are redacted, their file and line are not. GitHub deletes the artifact after 7 days. To keep the full report private, run rechtzeitig from a private repository; a website-only scan needs no checkout.

Security tab

With sarif-upload: auto, findings also show as code scanning alerts in the Security tab, which only people with write access see. A weekly run updates the alerts and closes fixed ones. The job needs:

permissions:
  contents: read
  security-events: write
  actions: read # private repositories only

Public repositories have code scanning for free. rechtzeitig skips the upload with a notice for private repositories without GitHub Code Security, for runs from forks or Dependabot, and without security-events: write. The upload never fails the job. false asks GitHub nothing.

§ 7How the website is visited

Each page loads in a fresh Chromium, without and with JavaScript. Nothing is clicked and no consent is given, so every request and cookie in the report happened before consent. rechtzeitig opens the start page, the legal pages, a sample of other pages, and paths that must not be public (/.env, /.git/config).

GitHub's runners are in the US, so a banner shown only to EU visitors is missing. Pages behind a login are not checked.

§ 8Data that leaves the runner

Besides your website (its pages, the paths in data/probes.yml and the source maps its own scripts point to, up to code.max_maps) and the GitHub API of your repository (the Security tab upload, off with sarif-upload: false), rechtzeitig sends data only to:

ServiceWhat is sentWhen
api.osv.devName and version of all locked components, for example pkg:npm/lodash@4.17.21, including internal packagesBy default, when the repository is scanned. Turn it off with vulnerabilities: false
ipinfo.ioIP addresses of third-party servers that rechtzeitig does not knowOnly when IPINFO_TOKEN is set
api.thegreenwebfoundation.orgHost name of the start page, for example www.example.deBy default, when a website is scanned. Turn it off with green-hosting: false

§ 9Safe use

Never run rechtzeitig on pull_request_target: it gives code from a fork your secrets and a write token. Use workflow_dispatch, schedule, push or pull_request.

Check out with persist-credentials: false; rechtzeitig needs no token.

The scanned site is untrusted, so Chrome runs with its sandbox; without one the scan stops (require-sandbox: false scans anyway, only for sites you trust). No request reaches private addresses except the host of url.

The action sets up Node 24, which stays on the PATH. Set up your own Node after it, or use a separate job.

§ 10Updates

The example workflow pins a release by its commit SHA. Dependabot moves the pin with a pull request for each new release, see How do I get the latest version? Without it, copy the uses: line from the latest release.

§ 11Why rechtzeitig opens no issues

On a public repository, issues would point everyone to a weakness of your site. If you want one anyway, add a step that reads rechtzeitig-report.json and runs gh issue create.

Findings are technical risk hints with location and legal basis, not legal advice.
