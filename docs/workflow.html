§ 1Inputs

InputDefaultMeaning
urlemptyStart page to check. Empty scans only the repository.
languagedeLanguage of the site: de, en or all. Decides which words count as "Impressum", "Datenschutz" and so on.
subscriptionsfalsetrue if visitors can sign up for subscriptions. Turns on the cancellation button check (§ 312k BGB).
salesfalsetrue if consumers buy or sign contracts on the site. Turns on the withdrawal button check (§ 356a BGB).
modulesallComma list of check groups: legal, privacy, security, sustainability, accessibility, repo.
report-languagelanguagede or en. Titles and fix hints follow it; check messages are English.
fail-onneverWhen the run turns red, see fail-on.
max-pages10Pages to visit at most.
repositoryworkspaceFolder to read lockfiles, licenses and secrets from. Needs actions/checkout before rechtzeitig.
ipinfo-tokenemptyOpt-in. Token from ipinfo.io, passed from the secret IPINFO_TOKEN. Turns on the third-country check. Empty skips it, see Secrets.
vulnerabilitiestrueLooks up known vulnerabilities of locked components at osv.dev. false sends nothing there and the vulnerability check is skipped.
retention-days7Days GitHub keeps the report artifact, see The report.

The output result is pass, warn or fail.

§ 2Website, repository or both

The example workflow does both. Without actions/checkout there is nothing to read, so only the website is checked. Without a URL only the repository is checked.

§ 3fail-on

Every check ends as pass warn fail info or skip. fail-on decides which of these make the run red. The report is the same either way.

fail-onRun is red when1 fail, 2 warn0 fail, 2 warn
never (default)nevergreengreen
failany check failsredgreen
warnany check fails or warnsredred

The default never turns a run red, so adding rechtzeitig cannot break anything. Choose fail once the findings are fixed and you want to keep it that way, or warn before a launch.

§ 4Secrets

Every check that needs an API token is opt-in. It runs only when you add the token as a repository secret. Without the secret it shows as skip in the report, and nothing is sent to that service. All other checks need no secret.

SecretInputTurns onToken from
IPINFO_TOKENipinfo-tokenTransfers outside the EU (LEG-EU-DSE-005)ipinfo.io, the free plan is enough

To add a secret: repository Settings → Secrets and variables → Actions → New repository secret, with the name from the table. The example workflow already passes it to the input.

rechtzeitig sends only the IP addresses of third-party servers to IPinfo, never data about your visitors.

§ 5The report

The summary page of the run shows a table of all checks with details. The artifact rechtzeitig-report contains:

FileContent
rechtzeitig-report.mdThe same report as Markdown
rechtzeitig-report.jsonFindings: rule id, severity, status, message and locations. No page text or file contents
rechtzeitig-sbom.cdx.jsonSBOM in CycloneDX 1.6 format, with vulnerabilities

Keep the SBOM with each release. It shows which versions you shipped and that you checked them.

GitHub deletes the artifact after retention-days (default 7). On a public repository anyone signed in to GitHub can download it, including the list of your dependencies and where findings were found.

§ 6How the website is visited

Each page is loaded twice in a fresh Chromium, once with JavaScript off and once with it on. Nothing is clicked and no consent is given, so every request and cookie in the report happened before consent. rechtzeitig opens the start page, every legal page it finds, a sample of other pages, and a short list of paths that must not be public (/.env, /.git/config, backups).

GitHub's runners are in US data centers. A site that shows its consent banner only to EU visitors will look different here, and that is a finding in itself. Pages behind a login are not checked.

§ 7Data that leaves the runner

Besides visiting your website, rechtzeitig sends data to two services. Nothing else leaves the runner.

ServiceWhat is sentWhen
api.osv.devPackage URLs (name and version) of all locked components, for example pkg:npm/lodash@4.17.21When the repository is scanned and vulnerabilities is not false
ipinfo.ioIP addresses of third-party servers that rechtzeitig does not knowOnly when IPINFO_TOKEN is set

§ 8Safe use

Never run rechtzeitig in a workflow triggered by pull_request_target. That trigger runs with your secrets and a token that can write to the repository, while the scanned code comes from a fork. Use workflow_dispatch, schedule, push or pull_request.

Check out with persist-credentials: false as in the example workflow. rechtzeitig does not need the token, so it should not be left in the checkout.

rechtzeitig is a composite action and sets up Node 24 with actions/setup-node. That Node stays on the PATH for the steps after it in the same job. Set up your own Node version after rechtzeitig, or run it in a separate job.

Findings are technical risk hints with location and legal basis, not legal advice.
