Find the legal and security pitfalls that slip into AI-written code

rechtzeitig is a GitHub Action that checks your repository and your live website in one run: imprint (Impressum), privacy policy, cookie consent, leaked keys, security headers, vulnerable packages. Each finding names the place to fix and, where there is one, the law.

Copy the workflow See all 56 checks

Free and open source. It runs in your own CI with no account and no secret, and your code stays on the runner.

Repository and website, one report

  • Repository

    What visitors never see: committed keys, known vulnerabilities, license conflicts, risky workflows, open database rules. You also get a CycloneDX SBOM.

  • Website

    What visitors get: imprint and privacy policy, requests and cookies before consent, security headers, TLS and DNS. Runs when you set a url.

Today each check reads one side. Checks that compare both, such as the services in your code against your privacy policy, are next on the roadmap.

What it checks

  • Legal pages

    The German imprint (Impressum) under § 5 DDG and the privacy policy under the GDPR: linked, reachable, complete

  • Cookie consent

    Third-party requests and cookies before consent, the banner, transfers outside the EU, § 25 TDDDG

  • Shop and contract buttons

    Cancellation, withdrawal and order buttons under the BGB, and prices under the PAngV. In German: Kündigungsbutton prüfen

  • Security headers and TLS

    HTTPS, certificates, headers, exposed .env and .git files, error pages, SPF and DMARC

  • Repository and SBOM

    Committed secrets, also under public prefixes such as NEXT_PUBLIC_, Supabase tables without row level security, vulnerabilities from osv.dev, licenses, workflow risks

  • Sustainability and accessibility

    Compression, caching, image formats, green hosting, page language, autoplay

Add it in two minutes

  1. Copy rechtzeitig.yml to .github/workflows/rechtzeitig.yml in your repository.
  2. Set url and the language in the file.
  3. Wait for Monday or open Actions → rechtzeitig → Run workflow, then read the report on the run's summary page.

The example runs every week and fails when a check fails, so GitHub notifies you. Inputs, triggers, secrets and the report are described in Configuration.

The legal side

Each check names its legal basis where there is one and links primary sources: laws, courts, authorities and standards, never blogs. A finding is a technical risk hint with the place and the law, not legal advice. A clean report means these checks found nothing, not that the site is compliant.

All 56 checks were last reviewed against their sources between 3 November 2026 and 4 November 2026. A check not reviewed for a year fails the project's tests.

Manuel Steinberg (kreativ-anders) maintains rechtzeitig in Germany, open source under Apache-2.0. Each release lists what changed.

Questions

How do I get the latest version?

The workflow pins a release by its commit SHA. Add .github/dependabot.yml to your repository:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly

Dependabot then opens a pull request whenever a new rechtzeitig release is out. Merge it and you have the new version.

Does any data leave the runner?

Your source code does not. By default the names and versions of your locked packages go to osv.dev (vulnerabilities: false turns it off) and your host name to the Green Web Foundation (green-hosting: false). The full list is under Data that leaves the runner.

Who can see the report?

On a public repository the run page shows only counts by default, because anyone can read it; the findings go to the Security tab, which only people with write access see. For the full report on the run page, run rechtzeitig from a private repository, or set report-visibility: full to publish it. More in The report.
