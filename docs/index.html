rechtzeitig

A GitHub Action you start by hand. It opens your website as a new visitor from Germany would, reads your repository and points out technical signs that German and EU requirements may be missing, with the place it found them and the law they relate to.

rechtzeitig does not give legal advice and cannot tell you that your site is compliant. A finding is a hint to check, no finding is no all-clear.

What it does differently

  • Website and repository in one run

    It opens your live site and reads your repository in the same run, so one report covers what visitors receive and the code you ship.

  • German law, with a source for each check

    Every check links the sources it is based on, such as the law on gesetze-im-internet.de or EUR-Lex. A check whose last review is more than a year old fails our own tests.

  • Security and SBOM included

    Headers, TLS, exposed files and committed secrets are checked alongside the legal points. The same run writes a CycloneDX SBOM and looks for known vulnerabilities and license conflicts.

  • Your code stays on the runner

    Everything runs on GitHub's runners, and your source code is not uploaded anywhere. You need no account, and there is no paid tier.

Start in two minutes

  1. Copy rechtzeitig.yml to .github/workflows/rechtzeitig.yml in your repository.
  2. Open Actions → rechtzeitig → Run workflow, enter your URL and pick the language.
  3. Read the report on the run's summary page.

You need no secret to start. Checks that call an API with a token run only after you add that token as a repository secret. Without it they are skipped and send nothing. See Secrets.

Sends data to api.osv.dev
One official API without a token is on by default: the vulnerability lookup sends the names and versions of your locked packages to osv.dev. Turn it off with vulnerabilities: false. See What runs when.
