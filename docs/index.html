rechtzeitig

A GitHub Action that checks your website and repository for German and EU legal basics and security, and writes an SBOM. Each finding names the place and the law.

checked§in time
  • Imprint and privacy policy

    DDG, GDPR

  • Consent

    Third-party requests and cookies before consent, the banner, TDDDG

  • Contract buttons

    Cancellation and withdrawal, BGB

  • Security basics

    HTTPS, TLS, headers, exposed files, error pages, email spoofing

  • Repository

    SBOM, known vulnerabilities, license conflicts, committed secrets

Start in two minutes

  1. Copy rechtzeitig.yml to .github/workflows/rechtzeitig.yml in your repository.
  2. Open Actions → rechtzeitig → Run workflow, enter your URL and pick the language.
  3. Read the report on the run's summary page.

No account and no secret needed. Inputs, secrets and report files: The workflow. Every check and its law: All checks.

Questions

How do I get the latest version?

The workflow pins a release by its commit SHA. Add .github/dependabot.yml to your repository:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly

Dependabot then opens a pull request whenever a new rechtzeitig release is out. Merge it and you have the new version.

Is this legal advice?

No. A finding is a technical hint to check, no finding is no all-clear.

Does any data leave the runner?

Your source code does not. By default the names and versions of your locked packages go to osv.dev (vulnerabilities: false turns it off) and your host name to the Green Web Foundation (green-hosting: false). The full list: Data that leaves the runner.

Who can see the report?

On a public repository, only counts by default, because the run page is public. For the full report, run rechtzeitig from a private repository. See The report.

Findings are technical risk hints with location and legal basis, not legal advice.
