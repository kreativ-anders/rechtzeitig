Find the legal and security pitfalls in fast-built and AI-written code

rechtzeitig is a vibe code checker for any web project, hand-written or AI-built: a GitHub Action that checks your repository and your live website against German and EU law (GDPR, imprint, cookie consent) and security basics such as leaked keys, headers and vulnerable packages. Each finding names the place and the law.

What can go wrong

For solo developers with an AI-built site, small agencies, student projects and shop owners. Four findings that cost real money or trust:

  • Warning letter over a missing legal notice

    A site without the provider information required by § 5 DDG gets an Abmahnung. The check reads the linked page and the repository.

  • Fonts loaded from US servers

    Google Fonts sends every visitor's IP address to Google; LG München I, 20 January 2022, 3 O 17493/20 held that this violates the GDPR. The check finds the hosts in the code and on the site.

  • A tracker fires before consent

    § 25 TDDDG requires consent before non-essential cookies or trackers load. The check compares the requests with the banner.

  • An API key in a public repository

    Bots scan public repositories and try leaked keys within minutes. The check reads the code and the served JavaScript.

Add it in one step

  1. Copy rechtzeitig.yml to .github/workflows/ in your repository.
  2. Set your start page in it. Without a url only the repository is checked. 
    - uses: kreativ-anders/rechtzeitig@…
  with:
    url: https://www.example.com/
  3. Commit. It runs every Monday; start the first run under Actions → rechtzeitig → Run workflow. Findings show in the run summary and the Security tab, and GitHub emails you when a check fails.

  • Source maps do not expose the repository's code
  • Security headers from the repository reach the site

  • Website 53 checks

Sources, not advice

Each check names its legal basis and links primary sources: laws, courts, authorities. The maintainer, a developer and not a lawyer, checks every rule against those sources; findings are risk hints, not legal advice.

All 97 checks were last reviewed against their sources between 3 November 2026 and 14 November 2026. A check not reviewed for a year fails the project's tests.

Questions

How do I get the latest version?

The workflow pins a release by its commit SHA. Add .github/dependabot.yml to your repository, and Dependabot opens a pull request for each new release:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
Which laws does it cover?

German and EU law: GDPR, the German imprint and cookie rules (DDG, TDDDG), consumer rules for shops (BGB), accessibility (BFSG) and the Cyber Resilience Act. The security, license and code checks fit any project. Reports come in English or German. It runs on GitHub Actions; GitHub Enterprise Server is not tested.

Will it bury me in warnings?

Each finding is fail for a clear gap, warn for a likely one, or info for something to look at. Checks that do not apply, such as shop rules on a site without a shop, are skipped and say why. The example workflow fails the run only on fail (fail-on).

Does any data leave the runner?

Your source code does not. By default nothing about your project goes anywhere else. Two lookups are opt-in: package names and versions to osv.dev, your host name to the Green Web Foundation. See Data that leaves the runner.

Who can see the report?

On a public repository the run page shows only counts. The findings go to the Security tab, which only people with write access see. See The report.
