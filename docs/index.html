Find the legal and security pitfalls that slip into AI-written code

rechtzeitig is a GitHub Action that checks your repository and your live website: imprint (Impressum), privacy policy, cookie consent, leaked keys, security headers, vulnerable packages. Each finding names the place and the law.

Copy the workflow See all 85 checks

Free and open source by kreativ-anders. No account; your code stays on your runner.

checkedin time

Add it in one step

Copy rechtzeitig.yml to .github/workflows/ in your repository and set your url. It runs every Monday and GitHub emails you when a check fails. All options: Configuration.

What it checks

  • Repository

    Committed keys, known vulnerabilities, licenses, risky workflows, open database rules. Plus a CycloneDX SBOM.

  • Website

    Imprint, privacy policy, cookies before consent, security headers and TLS, Kündigungsbutton. Runs when you set a url.

  • Both together

    13 checks read the repository and the website together. They find what a scan of one side cannot see:

    • The database the site uses is secured in the repository
    • No secrets in the served JavaScript
    • Imprint and privacy policy without template data
    • Tracking ids from the code do not load before consent
    • Consent tool from the repository is active on the site
    • No development server or debug build in production
    • Privacy policy names the services in the code
    • Privacy policy names the hosting provider
    • Privacy policy names where forms send their data
    • Google Fonts: where the repository loads them
    • Source maps do not expose the repository's code
    • Security headers from the repository reach the site
    • The repository's security.txt is live

Sources, not advice

Each check names its legal basis and links primary sources: laws, courts, authorities.

All 85 checks were last reviewed against their sources between 3 November 2026 and 9 November 2026. A check not reviewed for a year fails the project's tests.

Questions

How do I get the latest version?

The workflow pins a release by its commit SHA. Add .github/dependabot.yml to your repository, and Dependabot opens a pull request for each new release:

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
Does any data leave the runner?

Your source code does not. By default package names and versions go to osv.dev and your host name to the Green Web Foundation; both can be turned off. See Data that leaves the runner.

Who can see the report?

On a public repository the run page shows only counts. The findings go to the Security tab, which only people with write access see. See The report.

Findings are technical risk hints with location and legal basis, not legal advice.
