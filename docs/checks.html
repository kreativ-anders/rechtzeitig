All checks

Every rule has a fixed id, so you can refer to it in tickets. Open a card to see how it is checked, how to fix it and where the code lives.

Results

  • passNothing to do.
  • failrechtzeitig is sure something is missing or wrong.
  • warnA pattern matched that a person should look at.
  • infoA list of things to judge yourself.
  • skipThe check does not apply, for example no URL was given.

The severity says how much a finding matters, from info to critical. Website checks run when you give a URL. Repository checks run when the workflow checks out your repository first. Lockfiles read: package-lock.json, pnpm-lock.yaml, yarn.lock, composer.lock, pubspec.lock, Cargo.lock, uv.lock, poetry.lock, requirements*.txt, go.mod.

Words and languages

Checks look for words like "Impressum", "Datenschutz" or "Alle ablehnen". The words live in one file per language, currently German and English. Pick the language of your site when you start the run; the page language check tells you if the choice looks wrong.

Findings are technical risk hints with location and legal basis, not legal advice.
